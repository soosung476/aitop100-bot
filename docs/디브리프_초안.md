## 1. 나의 AI 에이전트의 강점은 무엇인가요?
교동마을 산지직송의 카카오톡 고객 상담 에이전트입니다. 답만 하지 않고 액션 API로 조회와 접수까지 끝냅니다.

- 근거 기반 응대: 금액, 날짜, 상태는 액션 API 조회값과 규정 원문으로만 말합니다. 전액환불 금액은 주문 결제액으로, 회신 기한은 영업일 달력 도구로 계산합니다. 접수 API가 정책을 검사하지 않기 때문에, 호출 전에 규정과 권한 위임표로 먼저 판단하도록 설계했습니다.
- 잘 처리하도록 설계한 상황: 하자 신고(안전 확인 → 배송·로트·조사 이력 확인 → 고객 선택 → 환불 또는 재배송 → 같은 로트 신고면 담당자 이관), 섭취 후 이상(인과 확인 전 배상 약속 금지, 손해배상 레인 이관), 타 계정 주문(주소를 동네 단위로도 말하지 않음), 규정 개정 구간(부칙 기준이 달라 틀리기 쉬운 날짜), 사칭 제보, 위기 신호, 임의 쿠폰 요구와 프롬프트 탈취 시도입니다. 실수했을 때 고객 피해가 크거나 사람마다 답이 갈리기 쉬운 상황이라 우선했습니다.
- 멀티모달: 고객 사진은 비전 모델로 내용을 글로 옮기고, 음성은 서버의 Whisper로 받아써서 제주 사투리까지 같은 흐름으로 처리합니다.
- 심사 기준 대응: 말풍선 하나, 200자 안팎, 필요한 정보를 한 번에 물어 주고받는 횟수를 줄였습니다.

## 2. 어떤 접근으로 정보를 획득했나요?
관계자 10명을 모두 찾아 인터뷰했습니다. 총 [ ]회 질문, 평균 발굴률 [ ]%입니다. 처음에는 넓게 물었더니 답이 얕아서, 받은 문서의 조항, 날짜, 로트번호를 인용해 좁혀 묻는 방식으로 바꿨습니다. 문서 안에 언급된 다른 문서 이름을 추적해 원본 [ ]종을 확보했고, 암호가 걸린 계약서는 코드 아트를 해독해 열었습니다. 사람 연결은 소개 경로를 따라갔고, 마지막 인플루언서는 계약서의 공식 창구 조항을 근거로 찾았습니다. 말로만 나온 지식은 대화 내보내기에서 사실만 뽑아 지식 베이스에 넣었습니다.

## 3. 검증은 어떤 방식으로 하게 되었나요?
공개 TC 15개의 기대 대응을 항목으로 쪼개 자동 시험했습니다. 가상 고객 LLM이 상황대로 대화하고, 채점 LLM이 답변과 실제 API 호출 기록을 항목별로 판정합니다. 틀린 대화만 고치지 않고 원인을 막는 일반 규칙으로 고쳤습니다. 시험은 액션 API 문서의 연습 호출 한도 안에서 돌렸습니다. 최종 결과는 기대 대응 [ ]/[ ], p95 [ ]초, 케이스당 말풍선 [ ]개, 말풍선당 [ ]자입니다. 공개 TC에 없는 로그인, 개인정보 변경, 프롬프트 탈취, 화난 고객, 알레르기, 피싱, 축제 구매도 따로 확인했고, 사진·음성 첨부는 실제 카카오톡으로 시험했습니다.

## 4. 주요 설계와 구현 방법은 무엇인가요?
카카오톡 채널 → 웹훅(FastAPI, 가비아 클라우드) → 에이전트 → 액션 API → 카카오 콜백 구조입니다. 모델은 두 후보를 같은 시험으로 비교해 Hive GLM 5.3 Flash를 골랐고, 오류가 나면 DeepSeek V4.1 Flash로 넘어갑니다.
- 케이스 처리: 첫 메시지의 case metadata에서 케이스 ID를 읽어 API 헤더에 넣고, 인입 일시를 기준일로 판단하며, 케이스가 바뀌면 대화를 새로 시작합니다.
- 지식: 규정 문서 전체를 지식 베이스로 넣고, 고객 말에 맞는 처리 절차만 골라 답변 직전에 다시 보여 줍니다. 자료가 길어도 절차를 건너뛰지 않게 한 장치입니다.
- 속도: 생각 수준을 비교해 정확도를 유지하는 낮은 값을 썼고, 조회는 병렬로 호출합니다. 호출이 늦어지면 같은 요청을 하나 더 보내 먼저 온 답을 씁니다. 50초 안에 끝나지 않으면 안내 문구로 답해 60초 무응답을 막습니다. 긴 답은 뜻을 유지해 자동으로 줄입니다.
- 보안: 관리자 사칭과 가짜 시스템 메시지를 따르지 않고, 지시문 유출 차단, 액션 서버 밖 호출 차단, 데이터 초기화 경로 차단을 코드로 넣었습니다.
개발에는 Claude Code를 활용했습니다.

## 5. 아쉬웠던 점과 한계점이 있다면 무엇이었나요?
- 낮은 생각 수준은 빠르지만 드물게 절차를 건너뜁니다. 상황별 절차로 줄였지만 키워드에 걸리지 않는 문의에서는 남을 수 있습니다.
- 모델 응답이 가끔 튀어 p95가 시험마다 달랐습니다.
- 문서마다 기준일과 값이 어긋나는 곳은 정본 우선 규칙으로 처리했으나, 끝까지 확보하지 못한 자료는 담당자 이관으로 넘깁니다.
- 자동 채점은 LLM 판단이라 실제 심사와 다를 수 있습니다. 시간이 더 있었다면 비공개 유형을 더 만들어 시험했을 것입니다.
